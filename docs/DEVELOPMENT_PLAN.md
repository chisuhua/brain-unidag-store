## 1. 开发目标

### 1.1 核心目标

- **P0（必须完成）**：
  - Protobuf Schema v2.2 实现
  - IDAGStore 接口实现（SQLite + Zarr 本地存储）
  - 端到端加密（AES-GCM-256）
  - 确定性拓扑排序
  - brain-domain-agent 集成验证

- **P1（重要但可延期）**：
  - 云端存储实现（PostgreSQL + S3）
  - gRPC/HTTP API 服务
  - 性能优化（达到 KPI 目标）

- **P2（可选）**：
  - 多语言 SDK（Go、Java、JavaScript）
  - 可视化管理界面
  - 高级分析工具

## 2. 技术栈

### 2.1 核心技术

| 组件 | 技术选型 | 版本要求 | 理由 |
|------|----------|----------|------|

| **云端对象存储** | AWS S3 / MinIO | — | 可扩展性 |
| **加密库** | PyCryptodome | ≥3.15 | AES-GCM 支持 |
| **异步框架** | asyncio + aiohttp | Python 3.10+ | 高并发 |
| **RPC 框架** | gRPC | ≥1.50 | 高性能、类型安全 |

## 5. 质量保证

### 5.1 测试策略

| 测试类型 | 覆盖范围 | 目标 | 工具 |
|----------|----------|------|------|
| **单元测试** | 所有模块 | 覆盖率≥80% | pytest |
| **集成测试** | 跨模块交互 | 覆盖所有集成点 | pytest + docker |
| **性能测试** | 关键路径 | 满足 KPI | pytest-benchmark |
| **安全测试** | 加密/权限 | 无已知漏洞 | bandit + safety |
| **兼容性测试** | v2.0 → v2.2 | 迁移成功率100% | 迁移测试套件 |

### 5.2 代码审查流程

1. **自审**：提交前运行 `make lint test`
2. **同行评审**：至少1名同事 review
3. **架构评审**：架构师审查设计变更
4. **合并前检查**：CI 全部通过

### 5.3 持续集成

```yaml
# .github/workflows/ci.yml 示例
name: CI
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Install dependencies
        run: poetry install
      - name: Lint
        run: |
          poetry run black --check .
          poetry run flake8 .
          poetry run mypy .
      - name: Test
        run: poetry run pytest --cov --cov-report=xml
      - name: Security scan
        run: |
          poetry run bandit -r src/
          poetry run safety check
      - name: Upload coverage
        uses: codecov/codecov-action@v3
```

## 附录A：开发规范

### A.1 代码风格

- **Python**：遵循 PEP 8 + Black 格式化
- **命名**：snake_case（函数/变量）、PascalCase（类）
- **注释**：所有公共 API 必须有 docstring
- **类型注解**：所有函数必须有类型注解

### A.2 Git 工作流

- **分支策略**：Git Flow（main/develop/feature/release）
- **Commit 格式**：`<type>(<scope>): <subject>`
  - type: feat/fix/docs/test/refactor/perf/chore
  - 示例：`feat(storage): implement SQLite store`
- **PR 要求**：通过 CI + 至少1次 review

### A.3 发布流程

1. 创建 release 分支：`release/v1.0.0`
2. 更新版本号 + CHANGELOG
3. 运行完整测试套件
4. 合并到 main + 打标签
5. 发布 PyPI 包 + Docker 镜像
6. 发布 GitHub Release
